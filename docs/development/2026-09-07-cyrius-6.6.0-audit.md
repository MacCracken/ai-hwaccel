# Audit — cyrius `6.5.36 → 6.6.0`, bayan `1.5.2 → 1.5.5` (ai-hwaccel 2.3.21)

**Date:** 2026-09-07 · **Range:** 38 cyrius releases (6.5.37 … 6.6.0) + bayan
1.5.3–1.5.5 · **Outcome:** bump landed, 4 pre-existing defects filed, 1 CI gate
repaired, 1 error of my own corrected.

## Method, and its limits

Nine parallel readers over the upstream CHANGELOG range (split by version band),
the stdlib API surface, the bayan delta, the repo's own version references, and
the build/CI gates. They returned **142 findings — 67 no-op, 75 with claimed
impact**.

An automated adversarial verify pass was started and **deliberately cut short**:
it was fanning out three verifiers per finding with no cap and was on track for
~234 agents, which is disproportionate to a pin bump. 54 verdicts landed before
it was stopped, **26 of them refuting the finding under review** — a ~48%
refutation rate, which is the honest reason nothing below is asserted on an
agent's say-so.

**Everything load-bearing in this document was re-verified by hand**, with the
command and its output recorded. Where a claim is *not* independently verified,
it says so.

## 1. Findings that changed the release

### 1.1 The bayan bump is forced, and the two pairings fail in opposite ways ✅ verified

Not a courtesy bump. The arity gate is the **vendored `lib/result.cyr`** (whether
`Result` is declared `: stack`), not `cycc` — so both half-states are broken, in
opposite and asymmetric ways:

```
bayan 1.5.2 + 6.6.0 lib/   -> HARD COMPILE ERROR (loud)
    lib/bayan-json.cyr:811, :820
    "a `: stack` enum returns two values — bind both: `var tag, val = f();`"

bayan 1.5.5 + 6.5.36 lib/  -> BUILD SUCCEEDED, 0 errors, 0 warnings (silent)
    destructures a heap box pointer into a (tag, payload) pair
```

Both measured directly on a scratch clone. The silent direction is the dangerous
one and is why the manifest comment now spells out both.

### 1.2 `CYRIUS_DCE=1` finally eliminates ✅ verified

6.5.72 turned dead-code elimination from NOP-padding into real removal. CI, the
release job and every wheel-staging script already pass the flag, so this lands
on every shipped artifact. Built from the published release tarballs so the
cross-compilers match CI:

| target | 6.5.36 | 6.6.0 | Δ |
|---|---:|---:|---:|
| x86_64 ELF | 419 360 B | **214 592 B** | **−48.8%** |
| x86_64 PE | 489 984 B | 497 664 B | +7 680 B (+1.6%) |
| aarch64 ELF | 673 160 B | 673 184 B | +24 B |

Only the x86_64 ELF backend reclaims today. The PE growth is reported rather
than averaged away.

### 1.3 `#derive(accessors)` inline-replay ✅ verified

6.5.71 routes derived getters/setters through the inline-replay path. All 16
heap structs here are derived and the registry benches are close to pure
accessor traffic: **12 wins (2.3–55.8%), 3 neutral, 0 regressions**. Method and
the full table are in the 2.3.21 CHANGELOG entry.

⚠ **The A/B trap, recorded because it silently invalidated the first run:**
`~/.cyrius/bin` is a symlink to the newest install, and the `cyrius` wrapper
resolves `cycc` through it *regardless of the manifest pin* — it only **warns**
about drift. An A/B that does not force each arm's compiler (per-arm shadow
`CYRIUS_HOME`, plus a guard that aborts on the drift warning) measures the
stdlib swap alone and reports "0 regressions, 1 improvement" for what is
actually a 12-win change.

### 1.4 `cyrius lib sync` no longer completes `./lib/` ✅ verified

`lib sync` copies the 38 declared `[deps].stdlib` leaves. The new
`lib/hashseed.cyr` (6.5.39, required by the declared `hashmap` leaf) arrives only
via `cyrius deps`' transitive pass — 45 → 46 files. A fresh clone that runs
`lib sync` alone gets an incomplete tree. `CLAUDE.md`'s vendoring principle was
corrected.

### 1.5 `AI_HWACCEL_LOG` starts working on macOS and Windows ✅ verified

`src/log.cyr` reads it through the **stdlib** `getenv`, whose `_env_load` opened
`/proc/self/environ` unconditionally — so on macOS and Windows it returned 0 for
every name, and the variable had been a silent no-op there since 2.3.8. cyrius
6.5.45 derives `envp` from the init stack on macOS (`_macho_argv_base()`) and
calls the PE `GetEnvironmentVariableA` reroute (`0xF015`) on Windows.

`AI_HWACCEL_DATA_DIR` is **not** fixed by this — see §3.1.

### 1.6 arm64-macOS threading becomes real ✅ verified (source), ⚠ not runtime-tested

Through 6.5.43, Darwin `thread_create` ran the body inline and `thread_join` was
a no-op. 6.5.44 wires real pthreads plus a blocking `__ulock` mutex — which also
replaces the bare spinlock `cached_registry` was taking there. Verified by
reading the two stdlib snapshots; **not** exercised on real Apple hardware in
this pass. Worth a run on `ecb` before tagging. Exposes §3.3.

## 2. A gate I broke and then fixed

I wrote a `ci.yml` comment claiming `cyrius deps --verify` fails on a stale
committed lock. **That was false**, and testing it produced a real finding:

```
CI order  (cyrius deps; cyrius deps --verify) -> "46 verified, 0 failed", exit 0
                                                 (deps silently repaired the file first)
verify alone against the pre-bump lock        -> "30 verified, 15 failed",  exit 1
```

The preceding `cyrius deps` rewrites the lockfile, so the hash check is a
`lib/`-integrity assertion, **not** a lock-drift gate.

The fix is a content comparison after `deps`. My first attempt — `git diff
--exit-code cyrius.lock` — would have been **flaky**, which testing also caught:

```
5 successive `deps` runs over an existing ./lib/  -> byte-identical
1 clean-tree `lib sync` + `deps` (what CI does)   -> 6 lines reordered
```

`cyrius deps` emits hash lines in hash-map iteration order. The shipped gate
compares **sorted** content against `git show HEAD:cyrius.lock`, and was tested
both ways: passes on a clean rebuild that reorders lines, fails with 35
differing lines on this release's own pre-bump lock.

None are caused by this bump. Each changes behaviour on a shipped target, so each
gets its own version and its own benchmark delta rather than riding along.

| 3.2 | [`_monotonic_secs()` unguarded](issues/2026-09-07-monotonic-secs-unguarded-on-macos-windows.md) — bare `syscall(228, 1, &ts)`; the route *returns* the value on macOS/Windows and never fills `&ts`, so it reads uninitialised stack and cache TTL is undefined | both non-Linux wheels | source + `chrono.cyr` |
| 3.3 | [threaded detect vs single-threaded sakshi](issues/2026-09-07-threaded-detect-vs-single-threaded-sakshi.md) — detector threads log; sakshi is single-threaded on the default stderr target | Linux always; arm64-macOS as of §1.6 | source read |
| 3.4 | [`cache.cyr` raw syscalls wrong on aarch64](issues/2026-09-07-cache-raw-syscalls-wrong-on-aarch64.md) — 83/87 are not mkdir/unlink there; disk cache silently never creates or removes anything | `dist/` consumers on aarch64 (DCE'd out of the CLI) | **qemu-aarch64 probe** |

## 4. Consumer-facing risk (not ai-hwaccel's to fix)

- **`dist/ai-hwaccel.cyr` now needs a 6.6.0-class toolchain** *if* the consumer
  calls `profile_from_json_str` — because that consumer must supply a value-form
  bayan. A consumer that never calls it is unaffected (the symbols are
  unreachable and eliminated).
- **cyrius 6.5.50–6.5.55 miscompile prefix-colliding identifiers** — a shorter
  identifier that prefixes a longer one in the same bucket took the wrong pool
  offset. Exit 0, no diagnostic. ai-hwaccel never pinned inside that band
  (6.5.36 predates it, 6.6.0 contains the fix), but a consumer sitting in it can
  be miscompiled through no fault of this repo. *Reported by the audit; the band
  itself was not independently reproduced here.*
- **ai-hwaccel is an early adopter of the value form.** Per the upstream 6.6.0
  notes, the great majority of downstream repos were still below 6.5.60 at
  closeout. *Upstream's figures, not independently checked.*
- **Upstream, unfiled:** `cyrius build --aarch64` emits
  `lib/io.cyr:442:31: raw syscall 32 is x86_64 dup; on ELF-aarch64 that number is
  not a syscall at all`. That is in the cyrius stdlib, not this repo — belongs
  upstream, and the toolchain is not ours to edit.

## 5. Dismissed

67 findings were no-ops on inspection and are not reproduced here. The larger
categories: the entire 6.5.58–6.5.66 SIMD arc (this codebase has no floats and
does not vendor `lib/simd.cyr`); the `Result`/`Option`/`Either` value form itself
(zero hits for `payload(`, `tagged_new`, `unwrap`, `result_*`, `err_code_of`,
`is_ok`, `is_err_result` across `src/ tests/ benches/ fuzz/`); `ok_via`/`err_via`;
closure and `private`-scoping fixes; per-process hash seeding (no hashmap call
sites); and the `CYRIUS_DCE` unsoundness above 32 768 functions (this tree is at
~1 387).

Two claims were dropped as **unsupported on this host**:

- *"The manifest pin now binds the compiler end-to-end."* Contradicted by direct
  observation — building with pin 6.5.36 against an installed 6.5.36 produced a
  **drift warning and compiled with 6.6.0 anyway**, it did not redirect. Not
  claimed anywhere in the release.
- *"`cycc_aarch64` is missing from 6.6.0."* True of the **local install**, false
  of the release: the 6.6.0 tarball ships `cycc_aarch64` and `cycc_win`, and both
  cross-builds succeed from it. CI is unaffected. (The local
  `~/.cyrius/versions/6.6.0/` tree is incomplete and worth reinstalling.)

## 6. Coverage limits

- Everything ran on **x86_64 Linux**. macOS and Windows conclusions are from
  reading the stdlib snapshots; aarch64 conclusions from `qemu-aarch64`. The
  `ecb` / `ach` / `cass` legs were not run.
- The adversarial verify pass was stopped early (§ *Method*). Findings outside
  §1–§4 carry no second opinion.
- A green suite is not proof of absence for any of the miscompile bands in §4.
